Bumpgate is the merge gate for bot PRs. On every Dependabot or Renovate PR, Kane CLI replays your app's critical journeys in a real browser on main and on the bump. It merges only if nothing broke. If something did, Claude Code migrates the code and Kane proves the fix.

03 The rule

The agent proposes. Code decides.

No model votes on the merge. Kane observes, a few lines of code decide, a maintainer can always override. Three lights, three actions.

// src/gate.mjs: the whole merge decision
const comparable = rows.filter(r => majority(r.base) === 'pass');
const everyBasePassStillPasses = comparable.every(
  r => ['green', 'amber'].includes(decideJourney(r).light));

// fail closed: no comparison, no merge
if (comparable.length === 0) return 'hold';

// the fix agent can't touch the exam or undo the bump
guardrails({ files, journeysDir: '.kane', bumps, headPkg, newPkg });

Green · merge

Every journey that passes on main passes on the bump, with no heal and no new console errors. Auto-merge is enabled.

Amber · one look

It works, but Kane had to self-heal a step (the UI moved), or new console errors appeared. A human glances, then merges.

Red · block, then fix

A journey broke. Merge blocked. Claude Code migrates from Kane's evidence; Kane re-verifies; after 3 tries it's labelled needs-human.

04 Proof

Every verdict arrives with evidence.

Real library upgrades, real Kane runs. Every number links to Kane's own sealed evidence pack.

05 Why only Kane

A selector script breaks on the churn.

A recorded Playwright test

Breaks when a UI-kit major renames classes and wraps buttons, even when the shop works. So teams skip it on bot PRs, or it cries wolf and gets ignored.

  • Selectors tied to today's DOM
  • Someone writes and maintains the code
  • Pass or fail, nothing in between

A Kane CLI journey

Plain English like "Click Place order, verify the errors are shown". It survives cosmetic churn and fails on broken behaviour. When it only passes after a self-heal, that's the amber light.

  • Written in English, kept in .kane/*_test.md
  • Recorded once, replayed cheaply on every PR
  • A sealed evidence pack for every run
--override-start-url

The same journey runs against each PR build on localhost.

--local

CI replays never write back to Test Manager, so a heal on the bump can't rewrite main's recording.

test_md_adaptive_heal

Kane tells us when a replay only passed after healing: the amber light.

test_md_bug_verdict

Kane's own bug title and severity land in the PR comment.

.evidence

Screenshots, console and network for each step. The fix agent reads them; the PR shows the base and bump screenshots side by side.

Run it yourself

Clone the demo, then npx github:Maheswar-Sah00/bumpgate check against a bump branch. Kane does the rest.

 
# .github/workflows/bumpgate.yml
name: Bumpgate
on:
  pull_request:
    types: [opened, synchronize, reopened, labeled]
permissions: { contents: write, pull-requests: write, issues: write }
jobs:
  gate:
    if: github.event.pull_request.user.login == 'dependabot[bot]' || github.event.pull_request.user.login == 'renovate[bot]'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - uses: Maheswar-Sah00/bumpgate@main
        with:
          lt-username: ${{ secrets.LT_USERNAME }}
          lt-access-key: ${{ secrets.LT_ACCESS_KEY }}
          openai-api-key: ${{ secrets.OPENAI_API_KEY }}
